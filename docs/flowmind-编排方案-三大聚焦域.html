0. 一页主张

域（Domain）定入口与边界 → 剧本（Playbook）定端到端闭环 → 动作（Action）定原子能力与权限。
侧边栏从"功能目录"升级为情境式侧边栏（Agent 方向盘）——不再是"你有哪些功能"，而是"系统当前认为你最该干什么"。跨境商业域独立成域，通过 import 引用机制复用其他域/工作空间的能力，框架零改动。

2. 现状盘点（事实-代码）

2.1 已有资产

  • 基座：cordis 微内核（前后端同构、DI/事件/生命周期）src/kernel · lib/kernel
  • 前端插件三件套：ui-actions（动作注册表，L0/L1/L2）、page-context（页面即上下文）、component-kit（生成式 UI）
  • 三层动态生成：M3 对话内组件 / M4 动态工作流（保存团队 SOP）/ M5 动态页面
  • 编排骨架：workspace 注册表（7 空间派生侧边栏）+ journey 注册表（listing-launch、content-publish）
  • 渠道元数据：PLATFORMS 已含 xhs / wechat / douyin
  • 公众号：端到端发布已实现（content-studio/wechat + wechat.service）
  • 跨境：TikTok·国际站铺货 4 步旅程 + b2b 域（关键词趋势/Listing/生图/渠道/情报）
  • 权限与入口：L0/L1/L2 三级动作权限 + L2 确认卡；全局 Agent（智体球 + 抽屉 + ⌘K）
  • 在场层种子：agent-presence store（活动遥测）

2.2 缺口

  • 无「域」抽象（workspace 只有页面货架，journey 只有跨页旅程）
  • 小红书只有元数据，无创作/配图/审计/发布闭环
  • 跨境便捷缺口：询盘/RFQ、合规便捷（HS code/关税/清关）
  • 侧边栏仍是"功能目录"形态，与 Agent 状态无关

3. 编排模型：域 / 剧本 / 动作 / 渠道

入口层：情境式侧边栏 · 全局 Agent（智体球/抽屉/⌘K）· 命令面板
域层 Domain（薄壳）：内容运营域 · 跨境商业域 · 运行监控域
剧本层 Playbook：端到端闭环步骤链 = journey + M4 团队 SOP
动作层 Action：工具/MCP/技能 + 渠道 Profile + L0/L1/L2 权限
基座层：cordis · page-context · ui-actions · component-kit · agent-runtime · discovery · M3/M4/M5

4. 情境式侧边栏（核心 · 真正高级的前台设计）

4.1 哲学转换

旧：侧边栏 = 功能目录（人找功能，越滚越长 → ERP 感）。
新：侧边栏 = Agent 方向盘（系统当前认为你最该干什么 + 现在进行到哪一步，人在环中确认）。它从"静态导航"变成"在场层（Ambient）的载体"。

4.2 三层结构（自上而下）

分区内容驱动源
A 情境区（顶部·动态）Agent 状态胶囊（空闲/工作中/等待确认/出错）· 当前旅程进度条与步骤 · 下一步建议（可点执行）· L2 风险确认徽标agent-runtime 决策 + journey 进度 + ui-actions 权限态
B 域区（中部）3 个域入口 + 域内高频剧本（非全部功能页）· 动态角标（待采纳数/渠道状态/风险数）· 点击进入「域工作台」domain manifest + channel 状态 + 待办/草稿计数
C 系统区（底部·最小化）⌘K 命令面板 · 设置 · Agent 管理 · 记忆/自进化workspace registry（收容非高频入口）

4.3 动态状态机（侧边栏"活"起来）

系统状态侧边栏表现
Agent 空闲情境区显示"建议下一步"（来自 Agent 决策输出），点击即触发
旅程进行中情境区切换为步骤时间线（可跳转，失败步标红，L2 步带确认标记）
L2 挂起顶部红色确认徽标 + 影响面摘要，点击展开确认卡
有草稿待采纳显示"待采纳 N 项"，点击展开草稿列表（L1）
渠道异常域入口角标告警（如公众号 token 过期、小红书登录失效）

4.4 交互高级感

  • 域入口 → 域工作台：不是跳静态列表页，而是打开该域的 M5 动态页（剧本墙 + 渠道连接状态 + Agent 建议卡），随域配置生长
  • 快捷键：⌘K 全局命令面板（已有）；⌘1/⌘2/⌘3 切域；⌘G 回到当前旅程
  • 折叠 = 胶囊条：Agent 状态点 + 当前域图标 + 待办数——状态面板永不消失，折叠不是图标菜单
  • 情境区信息密度闸：同一时刻最多展示 1 条建议 + 1 条提醒，超出收进下拉，避免噪音（防"高级"变"吵"）

4.5 代码支撑

  • 复用：useSidebar store、agent-presence store、journey registry、workspace registry、ui-actions
  • 新增：`contextual-sidebar` 组件（情境区）+ `agent-context` store（情境状态聚合）+ domain manifest 扩展字段（playbooks/channels/imports）

5. 域引用机制（跨境独立成域再引用）

5.1 domain manifest 扩展

// lib/domains/types.ts — 新增域抽象
interface DomainManifest {
  id: string; label: string; icon: Icon;
  playbooks: PlaybookRef[]; // 域内剧本（对应 journey/M4）
  channels?: ChannelRef[]; // 渠道 Profile（xhs/wechat/...）
  imports?: DomainImport[]; // 复用其他域/工作空间的能力
  dataSources?: DataSourceRef[]; // 数据源声明
}
  • 注册表做拓扑校验：引用循环检测、缺失引用检测、孤儿能力检测（与 M4 工具白名单校验同构）
  • 侧边栏 / 编排中心 / 命令面板据此渲染「域聚合视图」：一个域 = 自身剧本 + 被引用能力的聚合入口

5.2 跨境商业域 manifest（示意）

export const crossBorderDomain: DomainManifest = {
  id: 'cross-border-commerce',
  imports: [
    { from: 'insight', reuses: ['keyword-trends', 'intel'] }, // 市场调研
    { from: 'listing', reuses: ['listing-generate', 'imaging'] }, // Listing/配图
    { from: 'channels', reuses: ['channel-accounts'] }, // 渠道上架
    { from: 'content-ops', reuses: ['content-matrix'] }, // 可选：营销内容
  ],
  playbooks: ['market-intel', 'listing-launch', 'rfq-quote', 'compliance-kit', 'data-review'],
}

6. 内容运营域落地（公众号 + 小红书，抖音后置）

  • 渠道 Profile ×2：公众号（长文 · 16:9 头图 · 排版 · 群发 L2）、小红书（图文笔记 · 3:4 · 话题标签 · 发布 L2）
  • 剧本：
    • 内容流水线（复用 content-publish，扩展小红书渠道）
    • 内容矩阵同步（新增）：一次创作 → 双平台改稿 → 分渠道审计 → 分渠道发布（各自 L2 确认）
  • 域工作台：剧本墙 + 渠道连接状态（公众号/小红书） + Agent 选题建议

7. 跨境商业域落地（独立成域 · 询盘/RFQ 与合规便捷优先）

7.1 询盘 / RFQ 剧本（P1 首轮）

需求卡 · 询盘报价闭环
  • 触发：用户在「询盘工作台」导入询盘（粘贴文本 / 上传文件；邮箱/IM 自动接入为 P2）
  • 系统行为：解析询盘（品名/规格/数量/目标市场）→ 匹配已有产品或供应商 → 生成报价草稿（价格策略/MOQ/交期）→ 合规预检（HS code/关税）→ 汇总为报价卡
  • 用户可见：可编辑报价卡（价格可改）· 合规预检结果 · L2 发送前确认（影响面展示）
  • 异常恢复：解析失败→人工补充结构化字段；价格策略缺失→用默认模板并标注"待校准"；合规数据缺失→明示降级
  • 验收：*成功* 给定询盘，产出可编辑报价卡 + 预检结果，L2 未批准绝不对外发送；*边界* 重复发送幂等
  • 依赖：产品/供应商库、报价策略源（默认模板 → 历史成交，待定）、合规便捷剧本

7.2 合规便捷剧本（P1 首轮）

需求卡 · 合规便捷卡
  • 触发：在 Listing/询盘流程中或独立入口输入商品（关键词或图片）
  • 系统行为：HS code 识别 → 目标国关税税率 → 清关文件清单 → 目的国法规提示 → 生成合规卡
  • 用户可见：合规卡（HS code / 税率 / 所需文件清单），可导出；数据缺失明确标注，不给看似精确的假数
  • 异常恢复：数据源不可用→知识库/手工兜底并标注降级（对齐需求卡 D 诚实标注）
  • 验收：*成功* 输入商品产出可导出合规卡；*边界* 无可靠数据时显示"暂无数据"而非编造
  • 依赖：合规数据源（P1 内置知识库/手工录入，MCP 数据源后置待定）

7.3 数据复盘剧本（P1 后置）

毛利/广告/销量一键分析报表——排在询盘/RFQ、合规便捷之后，作为域内第三剧本。

9. Non-goals（本期明确不做）

抖音渠道 Profile（内容域二期）｜独立站搭建（Shopify 类）｜复杂财税自动申报（只做便捷查询）｜广告资金自动投放｜询盘邮箱/IM 自动接入（P2）｜第三方开发者插件市场｜多租户计费（数据层归属列已预留）

10. 落地顺序（最小路径）

  1. 域抽象 + 情境式侧边栏骨架：domain manifest + 情境区先行（Agent 状态胶囊 + 旅程进度 + 下一步建议）
  2. 内容运营域：小红书 Profile（3:4 配图/笔记语气/xhs 发布 L2）+ 内容矩阵同步剧本；公众号沿用现有
  3. 跨境商业域独立：询盘/RFQ 剧本（首轮）→ 合规便捷剧本 → data-review 后置
  4. 编排留存：剧本保存为团队 SOP（M4 已有）；M5 动态页承载报价卡/合规卡/域工作台

11. 开放问题（收敛为 3 个）

  • 情境区信息密度上限：1 建议 + 1 提醒是否够？（先按此实现，走查后校准）
  • 询盘/RFQ 的报价策略来源：默认模板 vs 调历史成交？（P1 先用模板 + 标注）
  • 合规数据源：内置知识库 vs 接 MCP？（P1 先知识库 + 诚实降级）
