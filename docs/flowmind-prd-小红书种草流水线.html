小红书种草流水线（xhs-seed-pipeline）

前端设计为主 · 热榜引擎专门处理逻辑 · 发布并入现成 content-studio · 后端技能按需新增
版本 v0.2 状态：已端到端落地（前端+链路真实 · 外部云依赖待恢复） 方向：选题直接接小红书热榜

0. 范围与设计原则

本期做（前端为主）：5 步种草闭环前端 + 热榜引擎（多源归一化处理逻辑） + 发布并入 content-studio（xhs 就绪卡/一键复制）。
设计原则：① 前端设计为主，后端技能（热榜源/发布 MCP）按需新增占位，不提前设计；② 选题洞察能接就直接接小红书热榜，不依赖 keyword-trends 兜底；③ 几种热榜统一走一套专门处理逻辑（§3）；④ 发布页并入现成 content-studio 发布步，不新建页面；⑤ 抖音/矩阵同步/询盘报价本期不做。

3. 热榜引擎（核心 · 专门处理逻辑）

3.1 多源分类

小红书热榜不止一种，前端需按"榜型"分别接入并统一处理（榜名/字段以实际可接数据源为准，后端按需新增 adapter）：

榜型特征选题价值
综合热榜（全站热搜）全站实时热度、更新快大势热点，声量大但竞争高
垂类/行业热榜美妆/穿搭/美食/家居/旅行/母婴/数码等分榜与用户品类强相关，匹配分加成
话题/标签热榜#话题 维度热度直接给出话题标签候选
灵感/创作热点官方灵感中心式选题方向官方背书，适合笔记创作起点

接法：能接就直接接（第三方聚合 API / 网页接口 / 运营手工录入均以 adapter 接入）；每个榜一个 adapter，输出统一结构，前端无感。

3.2 处理管线（4 步，专门逻辑）

① 归一化 Normalize
多源 → 统一条目
title / category / heatRaw / source / rank / fetchedAt，各榜字段映射对齐
② 聚合去重 Aggregate
同题多榜合并
按 title 归一化（去空格/符号/大小写）合并，记录 hitBoards（命中榜数）
③ 过滤打分 Filter & Rank
去噪 + 综合分
过滤违禁/广告/低质 → 跨榜归一化 + 多榜加成 + 时效衰减 + 品类匹配
④ 选题包装 Package
产出选题卡
topic + angle 建议 + 话题标签候选 + 竞争度/时效提示，来源标注

3.3 打分公式（可复算 · 参数可调）

// score.ts — 前端热榜引擎打分（初始参数，走查后校准）
score = rankScore + multiBoardBonus + freshnessBonus + categoryMatch

rankScore // 单榜归一化：rankScore = max(0, 100 - (rank-1) × 2.5)，取命中榜中最高
multiBoardBonus// 多榜命中：每多命中 1 榜 +10，封顶 +30（同题多榜 = 综合热度更高）
freshnessBonus // 时效：首次上榜 < 4h 加 +10；4-24h +5；>24h 不加（热榜有生命周期）
categoryMatch // 品类：命中用户品类/垂类榜 +15（仅在垂类榜来源命中时加）

说明：参数为暂定初始值，口径与校准方式在 E2E 走查后调整；无任何可靠热度时不产出假分，只显示"暂无数据"。

3.4 前端消费（useHotTopics hook）

  • 输入：榜型选择（综合/垂类/话题/灵感，可多选）+ 用户品类偏好
  • 输出：选题卡列表（综合分排序）+ 每个卡的数据来源/抓取时间/降级标注
  • 降级：某榜源不可用 → 该榜 Tab 标"不可用"，其余榜正常，不整体阻断
  • 刷新：手动刷新 + 可选自动刷新（轮询间隔可配，默认关闭）

4. 需求卡（前端导向）

需求卡 A · 热榜引擎与选题洞察面板（新增 · 核心）
触发旅程 step1 进入选题页；或内容运营域工作台点「看热榜」。
行为前端热榜引擎拉取多榜 → 归一化/聚合/打分/包装（§3）→ 热榜面板多 Tab 展示；选题卡综合分排序，标注多榜命中、时效、品类命中、数据来源。
可见HotBoardTabs（综合/垂类/话题/灵感）+ TopicCard 列表；降级榜标注不可用。
异常单榜源失败 → 该 Tab 降级标注，其余榜正常；全失败 → 空态 + 手工输入选题兜底。
依赖后端热榜源 adapter（按需新增，占位）；打分参数常量。
验收成功：给定品类，热榜面板产出选题卡且多榜命中可见。边界：无可靠数据时显示"暂无数据"，不编造热度。
需求卡 B · 旅程接入（xhs-seed-pipeline · 5 步）
行为注册旅程，5 步绑定组件与动作；每步 page-context + agentHint；可保存团队 SOP（M4）。
验收E2E 直驱走通 5 步；SOP 保存后对新选题重跑。
需求卡 C · 种草创作（复用 + xhs 语气强化）
行为oneKeyGenerate 生成标题≤20字 + 正文 + 5-8 话题 + 2-3 变体；前端 DraftEditor 可编辑/切变体；从热榜选中话题自动预填标签。
验收产出平台化草稿（区别于公众号长文），变体 ≥2。
需求卡 D · 3:4 配图 + 合规审计（复用）
行为image-generate 按 3:4 出图；studio-audit 跑小红书/广告法规则，风险词前端标红 + 替换建议。
验收配图 3:4；风险词标红；通过后进入发布。
需求卡 E · 发布并入 content-studio（现成）
行为发布步按平台分派：platform=xhs → 就地 PublishPanel（检测发布能力：可用 → L2 确认卡；不可用 → 就绪卡 + 一键复制 + 配图打包下载，标注"需手工粘贴"）；platform=wechat → 沿用现成跳转公众号页。
可见L2 确认卡 / 就绪卡，同一发布面板内切换，不新建页面。
验收成功：xhs 无发布能力时一键复制可用、闭环不阻断。边界：未批准绝不对外；取消以正常结果回传不重试。

6. E2E 验收清单（沿用 listing-launch-p0 直驱模式）

  • 热榜引擎：多榜归一化/聚合去重/打分可复算（给定 mock 榜数据断言综合分）
  • 旅程 5 步直驱走通，动作权限分级正确（发布 L2）
  • 发布：xhs 无通道自动降级就绪卡，一键复制可用；wechat 跳转不受影响
  • SOP 保存后新选题重跑，每步成败可见
  • 降级：单榜源失败不整体阻断，空态可手工输入

7. 开放问题（不阻塞开工）

  • 热榜打分参数初始值（rankStep=2.5 / 多榜+10 封顶 30 / 时效窗 4h/24h）是否合适——E2E mock 走查后校准
  • 热榜 Tab 默认展开哪几个榜型？（建议：综合 + 垂类 + 话题，灵感收二级）
  • 自动刷新轮询是否开启？（建议默认关闭，手动刷新）
